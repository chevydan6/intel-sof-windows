# N100 ACX application playback investigation, 2026-10-14

The Lenovo 14e Chromebook Gen 3 / Google PUJJOTEEN speaker route previously produced an audible hardware tone with the SOF IPC3 firmware and HDA DMA path; see `n100-speaker-tone-test.md`. This test asked whether an ordinary Windows audio app could use the development ACX speaker endpoint.

On branch `feature/acx-speaker`, CI WDK build `38408673620` produced a signed combined probe and ACX driver. It temporarily bound to the Intel N100 audio controller (`PCI\VEN_8086&DEV_54C8`), started, and Windows showed an OK `AudioEndpoint` named `Speakers (N100 SOF speaker (development))`. The firmware session booted, IPC3 pipeline and PCM parameter replies were zero, and `test-speaker-tone.ps1 -LeavePrepared` left the path ready. `test-acx-playback.ps1` generated a 48 kHz stereo WAV and called `System.Media.SoundPlayer.PlaySync`. The call returned, but the driver reported zero streams, runs, packets submitted, packets completed, and hardware position. The script now treats any of those zero counters as a failure, rather than calling that test a pass. It cleaned up the PCM params and firmware session, with `RestoredAdspcs=0x00000F0F` and `CleanupFlags=0`.

CI WDK build `38409660762` added stream creation attempt and failure-stage counters. With that driver, `waveOutOpen` for both the default device and device 0 returned `MMSYSERR_ERROR` (1). The driver recorded `CreateAttempts=0`, so neither call reached its `EvtAcxCircuitCreateStream` callback. A direct Core Audio probe using `IMMDeviceEnumerator` found one active render endpoint and returned `S_OK` for the default endpoint and `IMMDevice::Activate(IID_IAudioClient)`. `IAudioClient::GetMixFormat` and `IAudioClient::Initialize` returned `0x80070005` (`E_ACCESSDENIED`), again with zero create attempts. The same result occurred in the signed-in desktop session 1, so SSH session isolation was not the cause. `GetDevicePeriod` and `IsFormatSupported` with explicit 48 kHz stereo S32 also returned `E_ACCESSDENIED`.

Build `38421003199` aligned the ACX circuit name with the INF interface reference string `Speaker0`. Windows then copied the 48-byte `PKEY_AudioEngine_OEMFormat` from the INF to the endpoint, but the active `PKEY_AudioEngine_DeviceFormat` was absent. A temporary write to that endpoint property failed with `Requested registry access is not allowed`; no value was written. [Microsoft documents endpoint properties as set by the audio service and read-only to clients](https://learn.microsoft.com/en-us/windows/win32/coreaudio/audio-endpoint-properties).

The live controller's `DEVPKEY_Device_SecuritySDS` was `D:P(A;;GA;;;SY)(A;;GA;;;BA)`, inherited from the earlier `sofprobe.inx` package. Windows Audio (`Audiosrv`) runs as `NT AUTHORITY\LocalService`; it has no access under that descriptor. This is a strong candidate for `E_ACCESSDENIED`. Commit `069ad73` adds Local Service read/write/execute access in `sofplay.inx` and extends the Core Audio probe. WDK CI build `38422050078` passed. The candidate is **not yet validated**: replacing the package left Windows PnP paused during device restart (`setupapi.dev.log` stopped at `{Restarting Devices}`), and rebooting left the package staged but not bound. A second install paused at the same step. The live security descriptor therefore never changed, and playback could not be retested. Do not treat the build as a working audio driver.

Use `tools/check-coreaudio.ps1` to repeat the API diagnosis once a corrected package is bound. The next investigation should diagnose why PnP device restart stalls on package replacement, then retest the corrected descriptor and application playback. Check stream counters and audible output before claiming success.

After the stalled test, the temporary driver package, both test certificates, the interactive scheduled task, and test-signing boot setting were removed. A normal reboot was verified at 2026-10-14 00:35 local time: no SOF driver provider, service, package, test trust, or test-signing setting remained, and the controller showed its normal driverless/Stopped state.
